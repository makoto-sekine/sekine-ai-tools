# デスクトップ常駐型タイムラインマネージャー

## Problem Frame
一日の時間を何に使ったかを「実績」ベースで振り返りたい。予定ではなく実際にやったことを、作業中でも終わってからでも低コストで記録でき、後から日単位で振り返ったり日報に流用できる仕組みが個人用に欲しい。現状、記録を始めても入力コストが高くて続かない／後でまとめて思い出そうとすると抜け落ちる、という問題を解消する。

## Requirements
- R1. macOSデスクトップ背景に固定される縦型のタイムラインウィンドウを常駐させる。他のアプリより背面で、常に視界の隅に存在する
- R2. タイムラインは30分刻みのスロットで構成し、デフォルトの表示範囲は10:00–19:00。記録がその範囲外に存在する場合は、動的にスロットを拡張表示する
- R3. 隣接するスロットを結合して、1つの作業ブロックとして扱える（同じ作業が続いた時間帯をまとめられる）
- R4. 各スロット／ブロックには、自由記述のテキストとプリセットの色タグ（例：開発／会議／休憩 等）を1つ付与できる
- R5. 入力は「その場で書き込む（リアルタイム）」と「後からまとめて書き込む（振り返り）」の両方が自然にできること
- R6. 30分ごとにmacOS標準通知で入力を促す。通知はON/OFF切替可能で、通知をクリックするとアプリ内の該当スロットにフォーカスする
- R7. 過去の任意の日付に切り替えて、その日のタイムラインを閲覧できる
- R8. その日のタイムラインを、日報・レポートに流用可能な形（テキスト）として取り出せる手段を最低1つ備える

## Success Criteria
- 通常業務中に、作業を切り替えるたびに30秒以内で記録できている
- 1日が終わった時点で、ウィンドウを一目見ればその日何をしていたかが色と文字で直感的に把握できる
- 過去の任意の日を開いて、当時の作業ログが欠損なく参照できる
- その日のタイムラインから、日報などに貼り付けられるテキスト表現を取り出せる
- リマインダーをONにした日は、入力漏れスロットが目に見えて減る

## Scope Boundaries
- 客先・案件別の工数集計・時間集計機能は作らない（Phase 2以降）
- 複数デバイス間でのクラウド同期は作らない（ローカル保存のみ）
- マルチユーザー・チーム共有・閲覧権限は作らない（個人用ツール）
- 自動トラッキング（アプリ切り替え検知、カレンダー連携による自動入力など）は含まない
- 予定（これからやること）の管理は扱わない。あくまで実績記録に特化する

## Key Decisions
- デスクトップ背景固定型ウィンドウを採用：常に視界の隅に置いて入力の心理的コストを下げるため。フローティングだと他アプリと競合して邪魔になり得るため背面固定を優先
- 30分刻み + スロット結合：固定粒度による入力負荷を下げつつ、同じ作業が続くときはブロック化できる柔軟さを確保。完全自由入力は入力コスト側に倒れすぎる
- 色タグ + テキスト：タグ集計は不要だが、振り返り時の視認性を上げる最小限の構造として色タグを追加
- 時間範囲は動的伸縮：完全固定だと早朝・残業が記録できない。完全自由だと冗長。デフォルト10–19 + 範囲外記録で自動拡張の折衷案を採用
- 入力タイミングは「リアルタイム / 振り返り 両対応」：ユーザーの日によって運用が変わるため、どちらのモードも妨げない設計を基本に置く
- 日報エクスポート形式は初期スコープでは決めない：まずタイムライン入力自体が回るかを検証し、実データを見てから出力形式を詰める

## Dependencies / Assumptions
- macOSで動作するデスクトップアプリとして構築する（Mac常駐が前提）
- データは端末ローカルに保存する前提（クラウド同期は非ゴール）
- ユーザーはmacOSの通知許可をアプリに与える
- 主要な運用時間帯は平日日中だが、範囲動的伸縮により早朝・夜間も記録可能とする

### Deferred to Planning
- [Affects R1][Technical][Needs research] デスクトップ背景固定ウィンドウの実現方式（Swift/SwiftUI + `NSWindow.Level` 制御、Electron、Tauri など）の技術選定とトレードオフ評価
- [Affects R4][User decision] 色タグのプリセット初期セットと、ユーザーがカスタマイズできる範囲（追加／名称変更／色変更の可否）
- [Affects R3][Technical] スロット結合／分割の具体的な操作UI（ドラッグで範囲選択、Shiftクリックで複数選択、など）
- [Affects R7][Technical] 過去日ナビゲーションのUI（前日／翌日ボタン、日付ピッカー、ミニカレンダー表示のいずれか）
- [Affects R8][User decision] 日報エクスポートの具体仕様（Markdownクリップボードコピー／テンプレートカスタマイズ／ファイル保存 のどれを採るか）
- [Affects all][Technical] ローカルデータの保存形式（SQLite / JSONファイル）と保存先（Application Support 配下等）
- [Affects R6][User decision] 通知のデフォルトON/OFFと、アプリ起動していない時間帯でも通知を出すかの挙動
- [Affects R2][User decision] 時間範囲を動的拡張した場合の表示上の上限（例：0:00–24:00までは許容するか、スクロールで対応するか）
